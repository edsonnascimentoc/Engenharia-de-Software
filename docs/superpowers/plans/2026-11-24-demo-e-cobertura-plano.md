> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Close the README demo and coverage badge acceptance gaps with a real, sanitized CI demonstration and a verified Codecov upload.

**Architecture:** Keep the current GitHub Actions coverage generation and Codecov integration. Authenticate trusted uploads with a repository secret, make upload failures visible after setup, and record a short GIF of a real successful ALM quality-gate run using repository test data.

**Tech Stack:** GitHub Actions, Python `coverage.py` 7.10.6, Codecov GitHub Action v5, browser screen recording, Markdown.

**Spec:** `docs/superpowers/plans/2026-11-23-governanca-alm.md`, acceptance criteria for item 7 and evidence requirement for item 9.

## Global Constraints

- Do not include secrets, personal data, private logs, or issue bodies in the demonstration.
- Keep the existing GNU GPL v3 license unchanged.
- Do not claim a coverage percentage until Codecov processes an uploaded report.
- Preserve test and lint jobs as blocking CI checks; make coverage upload blocking only after its credentials and service integration are confirmed.
- Use a real GitHub Actions run or real local command output; do not fabricate terminal or UI output.

## Execution State and Prerequisites

- Local setup is implemented: the workflow creates `coverage.xml`, gates Codecov upload on a configured secret, and skips uploads for forks and Dependabot. Local verification passed: Python 3/3, Node 8/8, Ruff check/format, and documentation/RTM validation.
- Local coverage is 29% for `src/`; the ALM auditor itself currently has no tests. This is a local measurement, not a Codecov upload or a published badge value.
- The current feature branch has uncommitted changes, while GitHub `main` still has the earlier workflow. Remote evidence requires committing/pushing the feature branch, opening or updating a PR, and merging through the repository's normal review process.
- A repository owner must connect the repository to Codecov and add `CODECOV_TOKEN` under GitHub **Settings → Secrets and variables → Actions**. Never send the token in chat or store it in the repository. Dependabot uploads are deliberately skipped by the current workflow.
- Browser recording is pending: the earlier browser-control attempt was interrupted, so capture only after the browser is available and the user has finished interacting with it.

## Review Focus

- Coverage report is missing or empty: the upload must not create a misleading badge, and the workflow must show a clear failure after activation.
- Fork or Dependabot pull request has no upload credential: tests must still run, while coverage upload is skipped or uses an explicitly supported tokenless path.
- GIF shows secrets, personal data, or unrelated browser content: capture only the relevant workflow run and crop/redact before committing.
- README badge points to the wrong owner, repository, branch, or workflow: verify every rendered link against the repository slug and a successful `main` run.
- GIF is too large or inaccessible in the repository: keep it short, optimize it, and verify the relative README image link.

### Task 1: Verify and activate Codecov uploads

**Files:**
- Modify: `.github/workflows/alm-ci-quality-gate.yml`
- Modify if needed: `README.md`
- External configuration: Codecov project integration and GitHub repository/Dependabot Actions secrets

**Interfaces:**
- Consumes: `coverage.xml`, generated by the existing `coverage report` step in the `tests` job.
- Produces: a successfully processed coverage upload for `main` and an accurate README Codecov badge.

- [ ] **Step 1: Confirm the Codecov project and repository slug**

Open `https://codecov.io/gh/edsonnascimentoc/Engenharia-de-Software`, confirm the repository is connected, and confirm the service recognizes the `main` branch. If it is not connected, the repository owner installs/authorizes the Codecov GitHub App for this repository. Do not weaken organization-wide token requirements to enable uploads.

- [ ] **Step 2: Configure upload authentication**

Create a repository upload token in Codecov and save it in GitHub Actions as `CODECOV_TOKEN`; do not put the token in a file, workflow YAML, or chat. Dependabot uploads remain skipped; no Dependabot secret is needed for the planned configuration.

- [ ] **Step 3: Make the workflow enforce upload success for credentialed runs**

In `.github/workflows/alm-ci-quality-gate.yml`, add a `codecov-auth` step that reads the secret only in its environment and emits `configured=true` or `configured=false` to `$GITHUB_OUTPUT`; never print the token. Pass `${{ secrets.CODECOV_TOKEN }}` to `codecov/codecov-action@v5` and set `fail_ci_if_error: true`. Use this upload-step condition: `${{ steps.codecov-auth.outputs.configured == 'true' && (github.event_name == 'push' || (github.event_name == 'pull_request' && github.event.pull_request.head.repo.full_name == github.repository && github.actor != 'dependabot[bot]')) }}`. This uploads on pushes and trusted same-repository PRs, while fork and Dependabot PRs still run tests and generate coverage locally. Do not skip coverage generation or the test suite.

- [ ] **Step 4: Verify a push report and the resulting badge**

Commit the local changes, push the feature branch, and open/update a PR to `main`. Confirm all named checks pass and, when the secret is configured, the Codecov step uploads the report. Merge only through the repository's normal review process. Then confirm the post-merge `main` run produces a non-empty `coverage.xml`, the Codecov upload succeeds, Codecov displays the commit on `main`, and the README badge shows processed data. Open the badge link and confirm it resolves to this repository's Codecov page.

- [ ] **Step 5: Check PR credential behavior**

Inspect the same-repository PR and the post-merge `main` run. Confirm the upload runs only when `CODECOV_TOKEN` is configured, credentialed upload errors fail the upload step, and the token-check output contains only `configured=true/false`. Confirm fork and Dependabot PRs keep running tests and coverage generation while the upload step is skipped.
